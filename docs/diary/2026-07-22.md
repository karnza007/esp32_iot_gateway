# 2026-07-22

## M2 implemented: the link can now report its own failures

Wrote the Verilog for frame v2 and the matching host analyser. Full write-up in
[`../05-instrumentation.md`](../05-instrumentation.md).

**What changed**

- `framer.v` — 64-byte FIFO, `seq` / `ovf` / `cfg` header, payload checksum trailer.
  Header values are snapshotted at frame start so they cannot tear between their two bytes.
- `i2s_master_rx.v` — `BCLK_DIV` is now a parameter; `SCK_HIGH` and `SAMPLE_PT` derive
  from it, so every sweep point works without hand-editing constants.
- `uart_tx.v` — bit timer widened to `$clog2(CLK_PER_BIT)`. Not cosmetic: the overflow
  counter's positive-control test needs a deliberately slow baud rate, and a fixed 4-bit
  timer capped `CLK_PER_BIT` at 15.
- `top.v` — `BCLK_DIV` / `CLK_PER_BIT` / `NUM_CH` as parameters, packed into `cfg`.
- `inmp441_viewer.py` — parses v2, derives `fs` from `cfg`, verifies checksums, reports
  drop rate / overflow / integrity / throughput once per second, logs CSV, and prints a
  verdict naming which stage lost the data.

**Simulation** — `tb_framer` PASS, `tb_chain` PASS at all six sweep points
(15.000 / 18.750 / 23.4375 / 31.250 / 37.500 / 46.875 kHz). Payload matches the mic model
exactly at every rate, which re-confirms `CAP_START = 2`.

## Two things worth remembering

**T3 failed the first time, and the test was wrong, not the design.** After the stalled
drain recovered, the first checksum-valid frame in the stream was one that had been built
*before* the overflow and was still queued in the FIFO — it truthfully reported `ovf = 0`.
Fixed by flushing the backlog before starting the capture. Worth noting because it is the
same class of mistake as the earlier testbench-decoder bug: when simulation disagrees with
a design you have reason to trust, suspect the testbench first.

**The FIFO depth analysis came out smaller than expected.** Peak occupancy at the hardest
sweep point is about 14 bytes, so 32 would genuinely have been enough. Went to 64 anyway —
the depth has to stay frozen across the whole sweep for the points to be comparable, and
over-provisioning once now is cheaper than discovering a problem at sweep point four and
redoing points one to three. Documented honestly rather than pretending 32 was dangerous.

Also worth stating plainly in the report: **FIFO depth only buffers transients.** If the
average production rate exceeds the average drain rate, no depth helps. The FIFO does not
prevent saturation; the counters exist to report it.
